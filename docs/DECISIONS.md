## D-03 配置与上下文使用不同生效规则

Profile、Provider、MCP、工具白名单在进程启动时加载；修改后重启对应进程。CLI 退出后重新启动，服务端重启服务；首版不做配置热重载。

Bootstrap、已引用的 Skill 文件正文、MEMORY.md 每轮构建 Prompt 时重新读取，下一轮生效。改变 Profile 引用列表仍需重启。相同逻辑适用于 CLI 和 HTTP。

来源位置：需求 5.2 / 8.3，技术方案 5.3 / 8.2 / 8.3。实施：P-02、P-04、P-05；验收：A-02、A-05、A-07。

## D-04 首版密钥使用环境变量

API Key、Provider 和 MCP 凭证通过环境变量注入；配置只保存变量引用，不保存真实密钥。缺失或格式非法时明确报错，不把密钥输出到日志、接口响应、示例或版本库。

加密存储、密钥轮转、KMS/Vault 接入留到扩展阶段；不得宣称首版已实现这些能力。首版不提供独立明文密钥配置文件作为另一条加载路径。

来源位置：需求 5.12 / 8.5 / 初始化流程，技术方案 3.1 / 8.7。实施：P-02、P-08；验收：A-10；延期：E-04。

## D-07 工作区共享记忆，会话独立标识

首版定位个人或同一可信工作区。同一 `.oryxos` 下多个 Profile 共用 `memory/MEMORY.md`，不提供按用户/Agent 隔离的长期记忆；该边界应在文档中明确告知。

每次显式创建 Session 生成独立唯一 `session_id`。channel/user/profile 是归属字段，不是主键；同一组合允许多个独立会话。继续对话通过明确的 session_id 定位，不能静默合并同一组合的全部历史。具体 CLI 恢复入口和并发行为见 Q-04。

来源位置：需求 5.5 / 5.9 / Session 流程 / 数据模型，技术方案 5 / 9.2。实施：P-03、P-04、P-07；验收：A-04、A-05、A-09。

## D-08 私有部署不等于无外发

OryxOS 支持私有部署。是否向外传输数据取决于模型、HTTP 工具、MCP 等配置；调用外部服务时，请求中相关内容会传到对应服务。

“数据不出企业”必须以模型、工具和外发策略均满足要求为前提，不作为默认保证。企业级隔离、凭证治理和完整审计是后续目标，不是首版已有能力。

来源位置：调研 5.1 / 5.3 / 5.6，需求 1.1 / 设计目标 / 8.6。实施：P-09；验收：A-12。
